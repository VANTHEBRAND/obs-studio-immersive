# Scene editing behavior specification

Clean-room reference for re-implementing OBS Studio's scene-item transform
math and preview editing behavior on another platform (visionOS, Swift).

This document describes behavior only: inputs, outputs and rules. It contains
no OBS source code and is written so that an implementer who has never read
the OBS source can reproduce the behavior. Equivalence is proven by the test
vectors described in section 9, which are generated by running real libobs.

Process rules for the clean-room team:

- Implement from this document and the vectors only. Do not read
  `libobs/obs-scene.c` or `frontend/widgets/OBSBasicPreview.cpp`.
- Where this document and the vectors disagree, the vectors win. Report the
  disagreement so the document can be corrected.
- Where this document says "OBS is authoritative", the headset must adopt
  the value OBS reports instead of its own computation.

Terms used throughout:

| Term | Meaning |
| --- | --- |
| canvas | The OBS base resolution, in pixels. All transform values are expressed in canvas pixels. |
| item | A scene item: one placement of a source inside a scene. |
| group | A scene item whose source is a private scene holding child items. |
| box | The axis-aligned-then-rotated rectangle OBS draws the selection outline and handles on. |
| unit square | The square with corners (0,0), (1,0), (1,1), (0,1). The box transform maps it onto the canvas. |

## 1. Coordinate systems

**Canvas space.** Origin at the top-left of the canvas, x grows to the right,
y grows downward. Units are canvas pixels. Rotation is in degrees; a positive
rotation turns clockwise on screen.

**Unit square space.** Each item's box is the image of the unit square under
the item's box transform. Handle identities are defined in this space, not by
their visual position: the "top-left" handle is always the image of (0,0),
even when the item is flipped so that point appears on the right.

**Item stretch space.** Used during stretch and crop drags. Origin at the
canvas-space image of the unit (0,0) corner, axes aligned with the item's
rotation, units are canvas pixels. It is the canvas space un-rotated about the
item's (0,0) corner. It does not undo flips.

**Group space.** Child items of a group express their transform in the
group's local pixel space. The group's draw transform (section 3.5) maps group
space to canvas space.

**Preview view space.** The on-screen preview widget. The canvas is fit into
the view preserving aspect ratio (section 4.1).

## 2. Scene item state

### 2.1 Inputs that define an item's geometry

| Field | Type | Notes |
| --- | --- | --- |
| sourceWidth, sourceHeight | unsigned integer | Current size of the item's source. Reported by OBS, never computed by the headset. |
| cropLeft, cropTop, cropRight, cropBottom | integer ≥ 0 | In source pixels. Negative values are clamped to 0 when set. |
| boundsType | enum | NONE, STRETCH, SCALE_INNER, SCALE_OUTER, SCALE_TO_WIDTH, SCALE_TO_HEIGHT, MAX_ONLY |
| boundsWidth, boundsHeight | float | Bounding box size in canvas pixels. Only used when boundsType is not NONE. |
| boundsAlignment | flags | Where the content sits inside the bounding box. |
| alignment | flags | Which point of the box the position refers to. |
| scaleX, scaleY | float | May be negative, which flips the item on that axis. |
| rotation | float degrees | |
| positionX, positionY | float | Canvas pixels. |
| cropToBounds | bool | Only has an effect with SCALE_OUTER, SCALE_TO_WIDTH and SCALE_TO_HEIGHT. |

Alignment flags are a bit set:

| Flag | Value |
| --- | --- |
| CENTER | 0 |
| LEFT | 1 |
| RIGHT | 2 |
| TOP | 4 |
| BOTTOM | 8 |

Valid combinations use at most one horizontal flag and one vertical flag.
If both LEFT and RIGHT are set, RIGHT wins. If both TOP and BOTTOM are set,
BOTTOM wins. The default alignment of a new item is TOP | LEFT (5).

Other per-item state the editor needs: `selected`, `locked`, `visible`, the
scene item id, the parent group's item id (or none), and whether the source
produces video. Items whose source has no video are never hit-tested,
drawn, or selected by the preview.

### 2.2 obs-websocket field mapping

obs-websocket 5 exposes exactly these fields under `sceneItemTransform` in
`GetSceneItemTransform`, `SetSceneItemTransform` and the
`SceneItemTransformChanged` event: `sourceWidth`, `sourceHeight`,
`positionX`, `positionY`, `rotation`, `scaleX`, `scaleY`, `width`, `height`,
`alignment`, `boundsType`, `boundsAlignment`, `boundsWidth`, `boundsHeight`,
`cropLeft`, `cropRight`, `cropTop`, `cropBottom`, `cropToBounds`.

`width` and `height` are derived: `scaleX * sourceWidth` and
`scaleY * sourceHeight`. They ignore crop and bounds and must not be used
for geometry. `boundsType` is a string such as `OBS_BOUNDS_NONE`.

`SetSceneItemTransform` validation, which the headset must respect or the
request is rejected:

| Field | Accepted range |
| --- | --- |
| positionX, positionY | -90001 to 90001 |
| rotation | -360 to 360 |
| scaleX, scaleY | any finite value whose product with the source size is within ±90001 |
| boundsWidth, boundsHeight | 1 to 90001 |
| cropLeft, cropRight, cropTop, cropBottom | 0 to 100000 |

Selection is exposed through `SceneItemSelected` (selection only, there is
no deselection event) and the `GetSceneItemList` response does not carry
selection. The proposed vendor event in section 8 fills that gap.

### 2.3 Scene order

Items are ordered bottom to top. "Topmost" means last in render order.
Enumerations of a scene visit top-level items only; children of a group are
visited only when a rule says the group is entered.

## 3. Transform core

All arithmetic in OBS is IEEE single precision (32-bit float). Integer casts
truncate toward zero. Integer division truncates toward zero. Implementers
should use 32-bit floats and the stated operation order to minimize
divergence from the vectors.

### 3.1 Effective cropped size

```
cropW = cropLeft + cropRight
cropH = cropTop + cropBottom
cw = (cropW > sourceWidth)  ? 2 : sourceWidth  - cropW
ch = (cropH > sourceHeight) ? 2 : sourceHeight - cropH
```

Comparisons are unsigned. A source whose size is 0 on either axis produces
divisions by zero below. Treat such an item as having no box: do not draw
handles for it and do not allow stretch on it.

### 3.2 Alignment offset function

`AlignOffset(flags, cx, cy)` takes two **integers** and returns a float pair:

```
x = 0
if RIGHT in flags:          x = cx
else if LEFT not in flags:  x = cx / 2      (integer division, truncates toward zero)
y = 0
if BOTTOM in flags:         y = cy
else if TOP not in flags:   y = cy / 2      (integer division, truncates toward zero)
```

The integer division matters. For cx = 37 the centered offset is 18, not
18.5. For cx = -37 it is -18.

### 3.3 Bounds fitting

Only applies when boundsType is not NONE. Inputs: cw, ch from 3.1,
scale (sx, sy), bounds (bx, by), boundsType, boundsAlignment, cropToBounds.
Outputs: the fitted scale, the draw origin contribution `boundsOrigin`, and
the clamped integer box size (which equals the bounds).

```
width  = cw * |sx|
height = ch * |sy|
itemAspect   = width / height
boundsAspect = bx / by
effective = boundsType
if boundsType == MAX_ONLY and (width > bx or height > by):
    effective = SCALE_INNER

if effective is SCALE_INNER or SCALE_OUTER:
    useWidth = boundsAspect < itemAspect
    if boundsType == SCALE_OUTER:  useWidth = not useWidth     (the original type, so a promoted MAX_ONLY never inverts)
    mul = useWidth ? bx / width : by / height
    sx *= mul ; sy *= mul
else if effective is SCALE_TO_WIDTH:
    sx *= bx / width ; sy *= bx / width
else if effective is SCALE_TO_HEIGHT:
    sx *= by / height ; sy *= by / height
else if effective is STRETCH:
    sx = copysign(bx / cw, sx) ; sy = copysign(by / ch, sy)
(MAX_ONLY that was not promoted leaves scale unchanged)

width  = cw * sx          (signed now)
height = ch * sy
widthDiff  = bx - |width|
heightDiff = by - |height|
boundsOrigin = AlignOffset(boundsAlignment, trunc(-widthDiff), trunc(-heightDiff))
```

Crop-to-bounds adjustment. Applies only when `cropToBounds` is true, the
boundsType is SCALE_OUTER, SCALE_TO_WIDTH or SCALE_TO_HEIGHT, and
`widthDiff < -0.1` or `heightDiff < -0.1`. The width axis takes priority if
both overflow.

```
cropWidth   = widthDiff < -0.1
flipped     = cropWidth ? width < 0 : height < 0
axisAlign   = boundsAlignment masked to that axis (LEFT|RIGHT, or TOP|BOTTOM)
if flipped:
    if axisAlign == CENTER:            boundsOrigin.axis *= 2
    else if axisAlign has TOP or LEFT: boundsOrigin.axis -= diff      (diff = widthDiff or heightDiff)
    else:                               unchanged
else:
    boundsOrigin.axis = 0
```

This adjustment also sets an internal extra crop that OBS applies to the
rendered texture. That extra crop does not change the box or the draw
transform for the current update and the headset does not need it.

Finally, flipped content is kept in place inside the bounds:

```
if width  < 0: boundsOrigin.x += width
if height < 0: boundsOrigin.y += height
```

### 3.4 Box transform and corners

```
if boundsType == NONE:
    boxW = sx * cw ; boxH = sy * ch           (original scale, signed)
else:
    boxW = bx ; boxH = by
baseOrigin = AlignOffset(alignment, trunc(boxW), trunc(boxH))
corner(u, v) = Rot(rotation) · ( (u * boxW, v * boxH) - baseOrigin ) + position
```

where `Rot(θ)` applied to (x, y) gives `(x cosθ - y sinθ, x sinθ + y cosθ)`
with θ in radians (`degrees * 0.0174532925199432957692369076848`).

The four box corners are `corner(0,0)`, `corner(1,0)`, `corner(1,1)`,
`corner(0,1)`. `boxScale` is `(boxW, boxH)`, signed.

As a 4×4 row-vector matrix (point' = point · M, with z = 0 and w = 1), the
rows are: x row = `(boxW cosθ, boxW sinθ, 0, 0)`, y row =
`(-boxH sinθ, boxH cosθ, 0, 0)`, z row = `(0,0,1,0)`, t row =
`(corner(0,0).x, corner(0,0).y, 0, 1)`. The vectors store matrices in this
row-major order (16 values: x row, y row, z row, t row).

### 3.5 Draw transform

The draw transform maps cropped source pixels `(px, py)` with
`0 ≤ px ≤ cw`, `0 ≤ py ≤ ch` to the canvas. The headset needs it only for
groups (3.7). It is given here because the vectors include it.

```
if boundsType == NONE:
    dsx = sx ; dsy = sy
    origin = AlignOffset(alignment, trunc(cw * sx), trunc(ch * sy))
else:
    dsx, dsy = fitted scale from 3.3
    origin = boundsOrigin + AlignOffset(alignment, trunc(bx), trunc(by))
draw(px, py) = Rot(rotation) · ( (px * dsx, py * dsy) - origin ) + position
```

In the NONE case the draw transform equals the box transform with the unit
square replaced by `(0..cw, 0..ch)`.

Platform note: in the NONE case with a negative scale, OBS converts the
negative float `cw * sx` to an unsigned integer before the alignment
function. That conversion is undefined in C. On x86-64 builds it yields the
expected negative integer; on arm64 builds it may saturate to 0, which moves
the drawn content away from the box for flipped items with CENTER or RIGHT
(or BOTTOM) alignment. The vectors record whatever the generating platform
did. Treat the box transform as the truth for handles either way.

### 3.6 Relative coordinate mode

Scene collections created with OBS 31 or later store positions, bounds and
scale relative to the canvas so that the layout survives a canvas resize.
Everything the headset exchanges with OBS is still in absolute canvas
pixels; this mode changes what comes back after a set.

Let `X, Y` be the canvas width and height.

- Position: stored as `((2 * px - X) / Y, 2 * py / Y - 1)`. Reported back
  as `((rx * Y + X) / 2, (ry * Y + Y) / 2)` and then **quantized to the
  nearest 0.5 pixel** with halves rounding up: `floor(v * 2 + 0.5) / 2`.
- Bounds: stored as `2 * v / Y`, reported as `rv * Y / 2`, quantized the
  same way.
- Scale: stored as `set * (Yref / Y)` and reported as `stored * (Y / Yref)`
  where `Yref` is the canvas height when the item was created. With no
  canvas resize the factor is 1.
- Quantization is skipped for group items and for items inside a group.
- Nested scenes and groups never rescale their scale value.
- The box transform in this mode is computed from the reported (quantized)
  absolute values.

Consequence: a position set to 123.4 reads back as 123.5. The headset must
always adopt the echoed value after a set (section 8).

In absolute mode (collections created before OBS 31 or migrated back) values
round-trip exactly, subject only to float precision.

### 3.7 Groups

A group is an item whose source is a private scene. Its children have
transforms in group space. Canvas position of a child point:

```
canvasPoint = child box transform, then the group's draw transform
```

i.e. compute the child's corner in group space with 3.4, then apply the
group's draw transform from 3.5 treating the group-space point as a source
pixel. The group's source size is the size OBS reports for the group source.

The group's source size and the children's positions are maintained by OBS,
not by the headset:

- The group scene's size is `ceil(maxX - minX), ceil(maxY - minY)` of the
  union of all children's box corners in group space.
- Whenever the group is resized, children are re-based so that the union's
  minimum corner becomes (0,0), and the group's own position is moved so its
  content stays in place on the canvas (for a group with boundsType NONE,
  the new position is the alignment anchor of the union rectangle mapped
  through the old group draw transform).
- The group resize happens on OBS's video thread on the next frame after a
  child changes, except while a drag defers it (section 5.7).
- When an item is added to a group its transform is converted from canvas
  space to group space such that it does not move visually. The vectors
  include this case: `canvas_corners` after grouping equal the corners
  before grouping within tolerance.

The headset must treat every group and child transform update from OBS as
authoritative and never predict the re-basing.

### 3.8 Degenerate cases

- Source size 0 on an axis: no box, skip the item for editing.
- Bounds with `by = 0` or `bx = 0`: division by zero; obs-websocket rejects
  bounds below 1, so this only arises from other clients.
- Crop sum larger than the source: effective size is 2 pixels.
- A box transform whose inverse does not round-trip its corners within
  0.01 canvas pixels (singular or near-singular) is treated as not visible:
  no outline, no handles, not hit-testable.

## 4. Preview overlay geometry

Lengths given in "pt" are logical screen points on the preview, independent
of zoom. Convert to canvas pixels by dividing by the canvas-to-logical-point
scale of the view.

### 4.1 Canvas to view mapping

Default (fit) mode, with the view size in physical pixels:

```
viewAspect = viewW / viewH ; baseAspect = baseW / baseH
if viewAspect > baseAspect: scale = viewH / baseH ; cx = int(viewH * baseAspect) ; cy = viewH
else:                       scale = viewW / baseW ; cx = viewW ; cy = int(viewW / baseAspect)
offsetX = viewW / 2 - cx / 2 ; offsetY = viewH / 2 - cy / 2      (integer division)
```

Pointer position in logical points to canvas pixels:
`((lx - offsetX / dpr) * dpr / scale, (ly - offsetY / dpr) * dpr / scale)`
where `dpr` is the device pixel ratio.

Zoom ("fixed scaling") mode uses a user-chosen scale and a scroll offset
instead of the fit; the mapping is the same shape with
`offset = (view - base * scale) / 2 + scrollOffset`.

On the headset this mapping is whatever the window layout is; it is local
state and never sent to OBS. Resizing the headset window changes only this
mapping.

### 4.2 Selection outline and handles

Drawn for every item that is selected or hovered, is not locked, has video,
and passes the visibility round-trip check of 3.8. Groups are entered: their
children are drawn in group space transformed by the group draw transform.

- Outline: the four box edges, 2 pt thick. Selected items use the selection
  color; hovered unselected items use the hover color.
- Crop markers: when boundsType is NONE and any crop value is positive, each
  edge with a positive crop on that side is drawn as a striped line in the
  crop color instead of the solid outline (selected items only; hovered
  unselected items draw plain hover lines).
- Handles: for selected items only, eight 8 pt squares centered on the
  images of the unit points (0,0), (0.5,0), (1,0), (0,0.5), (1,0.5), (0,1),
  (0.5,1), (1,1).
- Rotation handle: for selected items only. Attach point A is the image of
  (0.5, 0), or of (0.5, 1) when boundsType is NONE and scaleY is negative.
  Outward direction D is "up" in the item's rotated frame: the unit vector
  `Rot(rotation + groupRotation) · (0, -1)`. A 2 pt wide stem runs from A
  to A + 30 pt · D. A 12 pt diameter filled circle is centered at
  A + 32 pt · D.
- Default colors are red for selection, green for crop and blue for hover;
  all three are user configurable in OBS.

### 4.3 Overflow pattern

Beneath the scene, OBS tiles a 96-pixel checker pattern across the box of
every selected item (or every item when "always show overflow" is on,
nothing when overflow is hidden). It shows through wherever the item is
transparent, which is how an item that is cropped or extends off its source
is made visible. Optional on the headset.

### 4.4 Safe areas

When enabled, drawn in light gray over the canvas:

| Guide | Geometry (fractions of canvas width W and height H) |
| --- | --- |
| Action safe | rectangle inset 3.5% on all sides |
| Graphics safe | rectangle inset 5% on all sides |
| 4:3 safe | rectangle inset 16.25% horizontally and 5% vertically |
| Center ticks | from (0, H/2) to (0.1 W, H/2); from (W/2, 0) to (W/2, 0.1 H); from (W, H/2) to (0.9 W, H/2) |

### 4.5 Snap guides

While a move or stretch is snapping (section 5.6), OBS draws a full-height
vertical line at each x it snapped to and a full-width horizontal line at
each y, in the selection color. They are cleared on release.

### 4.6 Spacing helpers

Shown only when exactly one item is selected, it is not locked, its parent
group (if any) is not locked, and its box size is non-zero on both axes.

Take the unit-space side midpoints left (0, 0.5), right (1, 0.5),
top (0.5, 0), bottom (0.5, 1). Apply these relabelings in order:

1. If boundsType is NONE and scaleX < 0, swap left and right. If boundsType
   is NONE and scaleY < 0, swap top and bottom.
2. Let r = rotation + group rotation. If r ≥ 45: for each threshold
   t in 45, 135, 225, 315 with r ≥ t, rotate the labels one step:
   top takes left's point, right takes top's, bottom takes right's, left
   takes bottom's. If r ≤ -45: for each threshold t in -45, -135, -225,
   -315 with r ≤ t, rotate the other way: top takes right's, right takes
   bottom's, bottom takes left's, left takes top's.

Transform the four points to canvas space with the box transform. For a
child of a group, OBS composes with the group's scale, rotation and position
only, ignoring the group's alignment origin; replicate that, including the
inaccuracy.

Then draw four 2 pt lines in the selection color, each only if its length
is not negative:

| Label | From | To | Distance shown |
| --- | --- | --- | --- |
| 0 (top) | (top.x, 0) | top | top.y |
| 1 (bottom) | bottom | (bottom.x, H) | H - bottom.y |
| 2 (left) | (0, left.y) | left | left.x |
| 3 (right) | right | (W, right.y) | W - right.x |

The label text is the distance in canvas pixels truncated to an integer
followed by " px", placed at the midpoint of the line, offset 6 pt to the
side (above for the vertical pair, to the right for the horizontal pair).

## 5. Interaction

### 5.1 Pointer mapping and rounding

Convert the pointer to canvas pixels with 4.1. The press position and every
subsequent drag position are rounded to the nearest integer canvas pixel
(halves away from zero) before any editing math. Handle hit testing and
hover use the unrounded position.

### 5.2 Handle hit test

Performed on press and on hover. Radius R = 6 pt converted to canvas
pixels. Walk the scene's top-level items bottom to top:

- A selected item tests its eight handles: the images of the eight unit
  points under its box transform (then the parent group's draw transform
  when inside a group). A handle is hit when the distance to the pointer is
  less than R; within one item the closest wins, and on ties the earlier
  in the order TL, TC, TR, CL, CR, BL, BC, BR wins. Across items, any hit
  on a later (higher) item replaces a hit on an earlier item, whatever the
  distances.
- The same item then tests its rotation handle at point
  `A + 30 pt · D` as defined in 4.2 (with D including the parent group's
  rotation). It competes on the same closest-distance basis and records:
  the item's current rotation as `startRotation`; `rotatePoint` = the
  canvas (or group space) center of the box, i.e. the image of (0.5, 0.5);
  `offsetPoint` = `Rot(-rotation) · (position - rotatePoint)`.
- An unselected group is entered and its children are tested with the
  group's draw transform applied and the group's rotation added to D.
  A selected group is tested as a single item and not entered.

A hit handle fixes the stretch target item and handle for the whole drag.
If the item is locked, drags are ignored.

Hit data captured at press for stretch and crop:

- `startSize`: `(boundsWidth, boundsHeight)` if bounds are on, else
  `((sourceWidth - cropLeft - cropRight) clamped ≥ 0, (sourceHeight - cropTop - cropBottom) clamped ≥ 0)`
  multiplied component-wise by the raw (unfitted, signed) scale.
- `itemUL`: the image of unit (0,0), i.e. `corner(0,0)` of the box transform
  in the item's parent space.
- `toItem(q) = Rot(-rotation) · (q - itemUL)`,
  `toParent(p) = Rot(rotation) · p + itemUL`.
- `startCrop`: the item's crop at press. `startPosition`: its position.
- If the item is in a group, `invGroup` = inverse of the group's draw
  transform; every later drag position is mapped through `invGroup` before
  use, and the group's automatic resize is deferred until release.

### 5.3 Item hit test

`ItemAt(p, selectBelow)`: walk the top-level items bottom to top, skipping
items without video, locked items and invisible items. An item is under p
when the inverse box transform maps p to (u, v) with `0 ≤ u ≤ 1`,
`0 ≤ v ≤ 1`, and mapping (u, v) back lands within 0.01 of p. Keep the last
(topmost) hit, with this exception when `selectBelow` is true: when a hit
item is already selected, if some item below it was already hit, stop and
return that lower item; otherwise clear `selectBelow` and continue normally.
Groups are not entered; the group's own box is tested.

`SelectedAt(p)`: true if any selected item is under p, entering groups
(children are tested in canvas space through the group's draw transform).
Locked and invisible items are not skipped here, only items without video.

### 5.4 Press, move, release

State: `startPos`, `lastPos`, `mouseDown`, `moved`, `overItems`,
`cropping`, `selectionBox`, the stretch target from 5.2, `lastMoveOffset`.
Modifiers: Alt, Shift, Ctrl (Cmd on macOS), read at the time of each event.

Press (primary button):

1. Clear the remembered selection list. If Alt is down, `cropping = true`.
   If Alt, Shift or Ctrl is down, remember the current set of selected
   items (top-level enumeration, groups entered).
2. Run the handle hit test at the unrounded position.
3. `startPos` = rounded position. `overItems = SelectedAt(startPos)`.
   `lastMoveOffset = (0,0)`. Snapshot all transforms for undo.

Move while pressed, with `pos` = rounded position:

1. If nothing has moved yet, no handle was hit and `overItems` is false:
   perform a click selection at `startPos` (5.5), then recompute
   `overItems = SelectedAt(startPos)`.
2. Clear snap guides.
3. If a handle was hit: if the target is locked, ignore. Otherwise map
   `pos` through `invGroup` if grouped, then: rotation handle → Rotate
   (5.9); `cropping` → Crop (5.8); else → Stretch (5.7).
4. Else if `overItems`: Move (5.6).
5. Else: `selectionBox = true`; if this is the first movement, perform the
   plain click selection at `startPos` first; then box-select (5.5).
6. `moved = true`, `lastPos = pos`.

Release:

1. If not `moved`: click selection at the unrounded release position (5.5).
2. If `selectionBox`: apply the box selection result (5.5).
3. End the deferred group resize if one was started. Clear the stretch
   target, `cropping`, `selectionBox`, `moved`, snap guides. Hover becomes
   the item under the pointer.
4. Record an undo entry if any transform changed.

### 5.5 Selection

Click (no Ctrl): `item = ItemAt(p, selectBelow = true)`; select exactly that
item and deselect every other item, entering groups so children are
deselected too. If nothing is under p, everything is deselected.

Ctrl-click: `item = ItemAt(p, selectBelow = false)`; toggle its selection
and leave others unchanged. No-op when nothing is under p.

Box selection: let the rectangle be the min/max of `startPos` and `pos`.
The hovered set is every top-level item with video that is unlocked and
visible and satisfies any of: the current pointer `pos` is inside its box
(same test as 5.3); any of its four box corners or its box center lies
strictly inside the rectangle; any box edge intersects any rectangle edge
(segment intersection test). Hovered items draw the hover outline.

On release with `selectionBox`:

- If Alt, Ctrl or Shift was down at release, first re-select the set
  remembered at press.
- Then for each hovered item: Alt → deselect it; Ctrl → toggle it; else →
  select it.
- With no modifier, the plain click at drag start already reduced the
  selection to at most the item under `startPos`.

Every selection change is applied to OBS immediately and OBS emits
`SceneItemSelected` for items that became selected. Deselection has no
event in stock obs-websocket; see section 8.

### 5.6 Move and snapping

```
offset     = pos - startPos
moveOffset = offset - lastMoveOffset
if Ctrl not down: moveOffset = Snap(moveOffset)
lastMoveOffset += moveOffset
```

Then every selected top-level item that is not locked gets
`position += moveOffset`. An unselected group is entered with the offset
mapped by the inverse of the group's draw transform with its translation
removed (rotation and scale only), and its selected unlocked children are
moved by that mapped offset. A selected group moves as a whole; its
children are not moved individually.

`Snap(moveOffset)`:

1. Compute the union rectangle `[tl, br]` of the box corners of all
   selected items in canvas space. Groups are entered: selected children
   contribute their corners mapped through the group's draw transform,
   whether or not the group itself is selected. Offset the rectangle by
   `moveOffset`.
2. If snapping is disabled, return `moveOffset` unchanged.
3. `screenOffset = ScreenSnap(tl, br)` (below).
4. If source snapping is disabled, return `moveOffset + screenOffset`.
5. `d = SnapDistance / previewScale` (default 5 preview pixels converted to
   canvas pixels). Start `result = screenOffset`. For each unselected,
   visible top-level item in bottom-to-top order (groups not entered),
   let `[itl, ibr]` be its axis-aligned bounding box of box corners, and
   let `moving` be the union rectangle from step 1. Per axis, a candidate
   only applies when `result` on that axis is still within 1e-4 of zero,
   so the first snap found per axis wins:

   ```
   centerDelta = center(moving) - center(item)
   itemEdge.x   = centerDelta.x < 0 ? item.left  : item.right
   movingEdge.x = centerDelta.x < 0 ? moving.left : moving.right
   if |centerDelta.x| > (moving.width + item.width - 2d) / 2:
       movingEdge.x = centerDelta.x < 0 ? moving.right : moving.left     (not overlapping: snap outer edges)
   else if moving.width > item.width:
       itemEdge.x   = centerDelta.x > 0 ? item.left   : item.right       (overlapping and larger: invert)
       movingEdge.x = centerDelta.x > 0 ? moving.left : moving.right
   same for y with top/bottom and heights
   if |itemEdge.x - movingEdge.x| < d:            result.x = itemEdge.x - movingEdge.x ; guide at x = itemEdge.x
   else if |center(item).x - center(moving).x| < d: result.x = center(item).x - center(moving).x ; guide at that x
   same for y
   ```
6. Return `moveOffset + result`.

`ScreenSnap(tl, br)` with canvas size `(W, H)` and `d` as above, result
starting at (0, 0), each edge candidate applying only when the axis result
is still within 1e-4 of zero:

```
if screen snapping enabled:
    if |0 - tl.x| < d: result.x = -tl.x       ; guide x = 0
    if |W - br.x| < d: result.x = W - br.x    ; guide x = W
    if |0 - tl.y| < d: result.y = -tl.y       ; guide y = 0
    if |H - br.y| < d: result.y = H - br.y    ; guide y = H
if center snapping enabled:
    cx = br.x - (br.x - tl.x) / 2 ; cy likewise
    if |W - (br.x - tl.x)| > d and |W/2 - cx| < d: result.x = W/2 - cx   ; guide x = W/2   (overrides an edge snap)
    if |H - (br.y - tl.y)| > d and |H/2 - cy| < d: result.y = H/2 - cy   ; guide y = H/2
```

Defaults: snapping enabled, screen snapping on, source snapping on, center
snapping off, snap distance 5.

### 5.7 Stretch

Inputs: `pos` (rounded, mapped to group space if grouped), the handle flags
(LEFT, RIGHT, TOP, BOTTOM subsets), `startSize`, `toItem`, `toParent`,
Shift and Ctrl state.

```
tl = (0, 0) ; br = startSize
p = toItem(pos)
if LEFT in handle: tl.x = p.x   else if RIGHT in handle:  br.x = p.x
if TOP  in handle: tl.y = p.y   else if BOTTOM in handle: br.y = p.y
if Ctrl not down: SnapStretch(tl, br)
if sourceWidth == 0 or sourceHeight == 0: abort without changes
size = br - tl
if boundsType != NONE:
    if Shift down: ClampAspect(tl, br, size, (sourceWidth, sourceHeight))
    if tl.x > br.x swap ; if tl.y > br.y swap
    size = |size|
    set bounds = size
else:
    base = (sourceWidth - cropLeft - cropRight, sourceHeight - cropTop - cropBottom)   (current crop)
    if Shift NOT down: ClampAspect(tl, br, size, base)
    set scale = size / base          (component-wise, signed: dragging past the opposite edge flips)
anchor = AnchorPoint(tl, br, alignment)
set position = round(toParent(anchor))    (each component rounded to integer)
```

So without bounds, dragging keeps the aspect ratio by default and Shift
frees it; with bounds it is the opposite.

`AnchorPoint(tl, br, alignment)`: x = tl.x if LEFT, br.x if RIGHT, else
`(br.x - tl.x) * 0.5 + tl.x`; y likewise with TOP and BOTTOM.

`ClampAspect(tl, br, size, base)` with `baseAspect = base.x / base.y`,
`aspect = size.x / size.y`, and `sameSign` = both components ≥ 0 or both
≤ 0:

```
corner handle:
    if aspect < baseAspect: size.x = sameSign ?  size.y * baseAspect : -size.y * baseAspect
    else:                   size.y = sameSign ?  size.x / baseAspect : -size.x / baseAspect
top-center / bottom-center: size.x = sameSign ? size.y * baseAspect : -size.y * baseAspect
left-center / right-center: size.y = sameSign ? size.x / baseAspect : -size.x / baseAspect
size = round(size) per component
if LEFT in handle: tl.x = br.x - size.x   else if RIGHT in handle:  br.x = tl.x + size.x
if TOP  in handle: tl.y = br.y - size.y   else if BOTTOM in handle: br.y = tl.y + size.y
```

`SnapStretch(tl, br)`: map the four corners (tl, (br.x, tl.y), (tl.x, br.y),
br) through `toParent`, take their axis-aligned bounds, run `ScreenSnap` on
them (screen and center snapping only, no source snapping), then
`delta = toItem(toParent(tl) + screenOffset) - tl` and apply `delta.x` to
`tl.x` if LEFT or to `br.x` if RIGHT, and `delta.y` to `tl.y` if TOP or to
`br.y` if BOTTOM.

For a child of a group, the drag defers the group's automatic resize from
press to release, so the child's group-space coordinates are stable during
the drag; on release OBS re-bases the group (3.7).

### 5.8 Crop

Alt-drag on a handle. Inputs as for stretch plus `startCrop`.

```
tl = (0, 0) ; br = startSize
p = toItem(pos)
raw = item scale as reported (unfitted)
s = boundsType == NONE ? raw : (|raw.x|, |raw.y|)
maxTL = (-startCrop.left * s.x, -startCrop.top * s.y)
maxBR = (startSize.x + startCrop.right * s.x, startSize.y + startCrop.bottom * s.y)
```

Define per axis `lo` and `hi` as `min` and `max`, swapped to `max` and
`min` when that axis is flipped (boundsType NONE and the raw scale on that
axis is negative).

```
p.x = lo(p.x, maxBR.x) ; p.x = hi(p.x, maxTL.x)
p.y = lo(p.y, maxBR.y) ; p.y = hi(p.y, maxTL.y)
if LEFT in handle:   tl.x = p.x = lo(p.x, startSize.x - 2 * s.x)
else if RIGHT:       br.x = p.x = hi(p.x, 2 * s.x)
if TOP in handle:    tl.y = p.y = lo(p.y, startSize.y - 2 * s.y)
else if BOTTOM:      br.y = p.y = hi(p.y, 2 * s.y)
```

New crop, starting from `startCrop`:

```
LEFT:   crop.left   += round(tl.x / s.x)
RIGHT:  crop.right  += round((startSize.x - br.x) / s.x)
TOP:    crop.top    += round(tl.y / s.y)
BOTTOM: crop.bottom += round((startSize.y - br.y) / s.y)
```

New position (only applied when boundsType is NONE; with bounds the
position is unchanged):

```
ax = alignment ∩ {LEFT, RIGHT} ; hx = handle ∩ {LEFT, RIGHT}
newX = (ax == hx and ax != 0) ? p.x : (RIGHT in alignment ? startSize.x : (LEFT in alignment ? 0 : startSize.x * 0.5))
same for y with TOP/BOTTOM
position = round(toParent(newX, newY))
```

Crop and position are applied together as one update.

### 5.9 Rotate

```
angle = atan2(pos.y - rotatePoint.y, pos.x - rotatePoint.x) + 90°     (range (-90°, 270°])
if Shift down:
    for i in 0..24:  if |angle - (i*15 - 90)°| < 7.5°: angle = (i*15 - 90)°
else if Ctrl not down:
    snap(startRotation, 5°)
    for each s in -90, -45, 0, 45, 90, 135, 180, 225, 270, 315: snap(s, 5°)
```

where `snap(target, t)` replaces `angle` with `target` when
`|angle - target| < t`. The checks run in the listed order and each
compares the current, possibly already snapped, angle. Comparisons are in
radians.

```
position = rotatePoint + Rot(angle) · offsetPoint
rotation = angle in degrees
```

Both are applied together. The rotation handle shows a closed-hand cursor
while dragging.

### 5.10 Cursor shapes (desktop reference)

When hovering a handle, OBS picks a resize cursor by the handle's visual
orientation: it folds the item's rotation into octants of 45°, swaps
left/right or top/bottom for negative scales on corner handles, and maps the
result to diagonal, horizontal or vertical resize cursors; the rotation
handle shows an open hand. The headset is free to design its own affordance.

## 6. Writing changes back to OBS

| Operation | Fields sent |
| --- | --- |
| Move | positionX, positionY |
| Stretch, bounds on | boundsWidth, boundsHeight, positionX, positionY |
| Stretch, bounds off | scaleX, scaleY, positionX, positionY |
| Crop | cropLeft, cropTop, cropRight, cropBottom and, when bounds are off, positionX, positionY |
| Rotate | rotation, positionX, positionY |

Send one `SetSceneItemTransform` per item per frame at most, carrying all
fields the operation changed, and always send the final value on release.
Rotation must be within -360 to 360; the rotate algorithm already produces
values in (-90, 270]. Crop values must be non-negative.

Each accepted request makes OBS emit `SceneItemTransformChanged` with the
full transform. In relative coordinate mode the echoed position and bounds
are the quantized values of 3.6.

## 7. Equivalence tolerances

- Box and draw matrices, corners, canvas corners: absolute difference
  ≤ 1e-3 canvas pixels per component.
- Reported position, bounds, scale: ≤ 1e-4 absolute (position and bounds
  may differ from what was set by the quantization in 3.6; compare to the
  `reported` block of the vector, not to the `input`).
- Crop values and every truncated integer: exact.
- A mismatch at a truncation boundary (for example `cw * sx` landing within
  1e-5 of an integer) is a precision artifact of fused multiply-add on the
  generating platform; log it and move on only after confirming the
  neighbouring vectors agree.

## 8. Synchronization protocol with OBS

OBS is authoritative; the headset is predictive.

1. On connect, fetch the scene list, the current preview scene, and every
   item's transform (`GetSceneItemList`, `GetSceneItemTransform`).
   Compute boxes locally. Subscribe to `SceneItemTransformChanged`,
   `SceneItemSelected`, `SceneItemCreated`, `SceneItemRemoved`,
   `SceneItemListReindexed`, `SceneItemEnableStateChanged`,
   `SceneItemLockStateChanged` and the Studio Mode preview scene events.
2. During a drag, apply the operation locally every frame and send the
   resulting fields to OBS with a per-item sequence number kept on the
   headset. Render from local state.
3. Ignore inbound transform events for an item while it is under drag,
   except to detect divergence: if the echoed transform differs from the
   last value sent for that sequence by more than the tolerances in
   section 7, log the inputs.
4. On release, send the final value, then wait for its echo and adopt it as
   the new local state. This absorbs quantization and any group re-basing.
5. For every echoed transform, recompute the box locally and compare with
   the box OBS reports through the vendor event below. Differences beyond
   tolerance are logged as port regressions.

Proposed vendor event (not implemented yet; to be added to this fork
through obs-websocket's vendor API):

- Vendor name `obs-immersive`.
- Request `GetSceneItemBoxes` with optional `sceneUuid` (default: the
  preview scene in Studio Mode, else the program scene).
- Event `SceneItemBoxesChanged`, emitted on the scene's item transform,
  selection, deselection, add, remove, reorder, visibility and lock
  signals, coalesced to at most once per rendered frame. Payload:

```
sceneUuid, version (monotonic per scene),
items: [ {
  sceneItemId, groupItemId | null, index,
  selected, locked, visible, hasVideo,
  transform: { same fields as obs-websocket sceneItemTransform },
  boxScale: [w, h],
  boxMatrix: [16 floats, row-major x,y,z,t rows],
  drawMatrix: [16 floats],
  canvasCorners: [[x,y] × 4]      (composed with the parent group's draw transform)
} ]
```

The headset uses `canvasCorners` to draw and `transform` to predict. Until
the vendor event exists, the headset computes everything from
`GetSceneItemTransform` and the standard events, and selection state is
tracked locally.

## 9. Test vectors

Generated by `test/transform-vectors`, a small program linked against
libobs that creates items with known inputs and dumps what libobs computed.
One run writes one JSON file per coordinate mode. Format:

```
{
  "generator": { "libobs_version", "platform", "canvas": {"width","height"}, "coordinate_mode": "absolute" | "relative" },
  "cases": [ {
    "id", "name", "kind": "item" | "grouped_item",
    "input": {
      "source_width", "source_height",
      "position": [x, y], "rotation", "scale": [sx, sy], "alignment",
      "bounds_type": "OBS_BOUNDS_*", "bounds_alignment", "bounds": [w, h],
      "crop": {"left","top","right","bottom"}, "crop_to_bounds",
      "group": { same fields, present for grouped_item }           // the group's own transform as set
    },
    "reported": { "position", "rotation", "scale", "alignment", "bounds_type", "bounds_alignment", "bounds", "crop", "crop_to_bounds", "source_width", "source_height" },
    "output": {
      "box_scale": [w, h], "box_matrix": [16], "draw_matrix": [16],
      "corners": [[x,y] × 4],                                     // in the item's parent space
      "canvas_corners": [[x,y] × 4],                              // composed with the group when grouped
      "pre_group_corners": [[x,y] × 4],                           // grouped_item only: corners before grouping
      "group": { "reported": {...}, "source_width", "source_height", "box_matrix", "draw_matrix" }   // grouped_item only
    }
  } ]
}
```

The `item` cases are what a transform core port must reproduce from
`reported` (not from `input`, because of 3.6). The `grouped_item` cases
verify composition with a group whose state OBS computed; the port
reproduces `corners` from the child's `reported` block, `group.box_matrix`
and `group.draw_matrix` from the group's `reported` block and size, and
`canvas_corners` from both. `pre_group_corners` should match
`canvas_corners` within tolerance; that invariant is OBS's, not the port's,
and is recorded for diagnosis.

The generator runs an exhaustive sweep over all alignments, bounds types and
bounds alignments with a few fixed scales, rotations and crops, then a
seeded pseudo-random sweep over wide ranges, then grouped cases. The seed
and counts are command-line options so the Swift test suite can pin a
specific file.
