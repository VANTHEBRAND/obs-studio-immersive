# Existing projects: OBS Studio (and OBS-like production control) in VR/AR/XR headsets

Research date: 2026-10-22. Scope: prior art a team porting OBS into an "immersive" Qt app (Apple Vision Pro first, then Valve Steam Frame / SteamVR PCVR, then macOS-with-rendering-on-Vision-Pro) can learn from.

Method notes for the report writer: GitHub repo pages, Apple developer docs, and most web search results were reachable; apps.apple.com, obsproject.com, doc.qt.io, store.steampowered.com and several news sites were NOT fetchable from this sandbox (DNS/proxy blocked), so App Store / OBS-forum / Qt-doc facts below come from search-result snippets of those pages rather than full page reads. Star counts and "last activity" are as shown on the GitHub pages on the research date; several GitHub pages did not expose a last-commit date, which is flagged where relevant. Searched terms included: obs visionos, obs steamvr overlay, obs openvr, obs-websocket vr, Vision Pro OBS, Qt Quick 3D Xr visionOS, Qt for visionOS, RemoteImmersiveSpace, Producer Pad, OBS Blade, Touch Portal, Companion, OVR Toolkit, XSOverlay, Desktop+, wlx-overlay-s, ALVR visionOS, Steam Frame, Immersed/Virtual Desktop/Bigscreen, Blackmagic immersive, Switcher.

Headline: As of October 2026 there is **no OBS port, fork, or native OBS client for visionOS**, and **no project that renders OBS's preview/program video inside any headset as a first-class spatial UI**. The closest prior art is (a) one tiny, brand-new C++ SteamVR overlay that controls OBS over obs-websocket (no video), (b) generic SteamVR desktop-mirroring overlays (Desktop+, OVR Toolkit, XSOverlay, WayVR) that show the flat OBS window in VR, (c) iPad/iPhone obs-websocket remotes (OBS Controller is explicitly listed for visionOS; Producer Pad shows Program/Preview video via NDI or its own feed plugin), and (d) platform plumbing that is new and relevant: Qt Quick 3D Xr (Qt 6.8+, Technical Preview, visionOS + OpenXR) and Apple's macOS 26 `RemoteImmersiveSpace` / CompositorServices for Mac-rendered immersive content on Vision Pro.

## Key Question 1: Are there existing OBS ports, forks, or native clients for visionOS / Apple Vision Pro?

### Takeaway
No OBS port, fork, or visionOS-native OBS client exists; no OBS GitHub issue, OBS forum thread, or Qt/OBS discussion about a visionOS port was found. The only Vision Pro-listed OBS control app found is "OBS Controller" (an iPad-class obs-websocket scene switcher whose App Store listing shows an "Apple Vision / Requires visionOS 1.0 or later" compatibility line); everything else for Vision Pro is either an iPad app running in compatibility mode (unverified) or is about capturing the Vision Pro into OBS.

### Cited Findings
- **OBS Controller (Fallen Starlight AB)** — App Store listing shows "Apple Vision: Requires visionOS 1.0 or later"; the app is "focused on having a simple mobile scene switcher in OBS"; features: control stream/recording/virtual camera output, show/hide scene elements, mute audio sources; "In OBS v28 and later it should work out of the box", older versions need the obs-websocket plugin — [OBS Controller on the App Store](https://apps.apple.com/us/app/obs-controller/id1547228500). (Listing text was obtained via search snippet; the listing could not be fetched directly. Whether it is a native visionOS build or an iPad-compatible app marked as Vision-compatible is not stated.)
- Other iOS OBS remotes found do NOT list visionOS in their compatibility lines: "OBS Remote - Stream Control" (iPhone/iPad, connects over local Wi-Fi via OBS WebSocket) — [App Store](https://apps.apple.com/gh/app/obs-remote-stream-control/id6760621511); "OBS Control Lite" (iPhone/iPad) — [App Store](https://apps.apple.com/us/app/obs-control-lite/id6450905767); "Switcher Pro" (iPhone/iPad/Apple Watch) — [App Store](https://apps.apple.com/us/app/switcher-pro/id6754262874).

- OBS Blade's App Store listing is "Designed for iPad" and its GitHub README lists only App Store, Google Play, F-Droid and GitHub Releases; nothing about visionOS/Vision Pro appears in either — [OBS Blade App Store](https://apps.apple.com/app/id1523915884); [Kounex/obs_blade](https://github.com/Kounex/obs_blade).
- Touch Portal's App Store listing requires iOS 12+ and lists iPhone/iPad/iPod touch with no visionOS entry — [Touch Portal App Store](https://apps.apple.com/app/id1410172542).
- Searches of the OBS forum for "Vision Pro" returned no relevant thread (only an unrelated "Pro version?" thread) — [obsproject.com forum result](https://obsproject.com/forum/threads/pro-version.25205).
- A search for obs-studio GitHub issues mentioning "Vision Pro" or "visionOS" returned no matching issues (only unrelated macOS camera/virtualcam commits, e.g. [obsproject/rfcs PR 15](https://github.com/obsproject/rfcs/pull/15/files/e127b5d785b1cd59f0091cbc4e4151e2704e3e05)).
- The VDO.Ninja docs have a guide for streaming an *Apple Vision Pro point-of-view feed into OBS* (capture direction, not control) — [VDO.Ninja guide](https://docs.vdo.ninja/guides/stream-apple-vision-pro-and-iphone-to-tiktok-with-obs).
- Valve's Steam Link beta for Vision Pro (April 2026, TestFlight) streams PC games to a "freely placeable virtual window" but "doesn't include support for VR content"; Valve "has not said whether SteamVR will come to Vision Pro" — [Road to VR](https://roadtovr.com/valve-steam-link-beta-vision-pro-vr-games); [heise](https://heise.de/-11248635).
- ALVR's visionOS client (`alvr-org/alvr-visionos`, "Experimental visionOS client for ALVR - SteamVR on Apple Vision Pro!") is MIT, ~535 stars, 518 commits, 57 open issues, no GitHub releases listed; it was later published free on the App Store per Road to VR; the PC streamer runs on Windows/Linux only ("not supported on Mac yet") — [alvr-org/alvr-visionos](https://github.com/alvr-org/alvr-visionos); [Road to VR](https://www.roadtovr.com/steamvr-games-come-to-vision-pro-thanks-to-public-launch-of-free-alvr-app/).

### Inferences
- The Vision Pro "OBS" landscape is entirely obs-websocket remotes (iPad-class) and camera-source apps. A native, spatial OBS client would be first of its kind; the team should expect no reusable visionOS-specific OBS code.
- "OBS Controller" is the only candidate to install on a Vision Pro today to study how an iPad-class obs-websocket remote behaves in a visionOS window; it has no preview video and is a scene switcher, so it is a UX floor rather than a model.
- SteamVR-style overlays (Question 2) are structurally impossible on visionOS because there is no SteamVR/OpenVR runtime on Vision Pro (ALVR streams SteamVR *output* to the headset; Steam Link on Vision Pro is 2D-only). An immersive OBS on Vision Pro must be a visionOS app (SwiftUI/RealityKit/CompositorServices, or Qt Quick 3D Xr), not an overlay.

### Gaps
- Could not fetch the OBS Controller App Store page directly to confirm whether the visionOS entry is a native build or "Designed for iPad" compatibility, its last update date, or whether it works well on Vision Pro in practice.
- No Reddit (r/VisionPro, r/obs) threads about OBS on Vision Pro surfaced in search; absence of evidence, not evidence of absence.
- No YouTube demos of OBS-on-Vision-Pro were found.

## Key Question 2: What VR overlay/desktop tools do streamers use inside SteamVR to control OBS today?

### Takeaway
Streamers control OBS in SteamVR either by (1) mirroring the flat OBS window / a browser page into VR with a desktop overlay (OVR Toolkit, XSOverlay, Desktop+, and on Linux WayVR/wlx-overlay-s), optionally firing OBS hotkeys via wrist macros, or (2) one purpose-built, very new and tiny C++ overlay (nicolas-riera/OBS-SteamVR-Overlay) that talks obs-websocket v5 directly and draws its own panels on a controller/wrist and in the SteamVR dashboard. None of these renders OBS preview/program video except as part of a mirrored desktop window.

### Cited Findings
- **nicolas-riera/OBS-SteamVR-Overlay** — "lightweight SteamVR overlay for controlling OBS Studio from inside VR"; attaches to a controller and adds a tab to the SteamVR dashboard, "no desktop window"; C++ with VS2022/CMake, Winsock, Windows CNG (SHA-256/base64 for obs-websocket auth), D3D11 texture upload, stb_truetype text; uses obs-websocket v5 (OBS 28+), reads port/password from OBS's config file automatically; features: recording start/stop/pause/chapter/split, streaming, virtual camera, replay buffer, save clip, screenshot, scene selector (drop-down/list/page), studio mode, transition, full audio mixer (volume, mute, VU meters, balance, sync offset, monitoring, tracks 1-6), performance stats (FPS/CPU/render time/dropped frames), compact icon-only mode, transparent background, multi-language JSON, "snapshot mode" that renders pages to PNG without a headset; UI: wrist/hand overlay appears when you turn your wrist toward your eyes ("view angle and maximum distance similar to fpsVR"), point-and-trigger cursor or SteamVR laser, move bar/resize grip, Layout editor with Simple/Free (drag-and-drop grid) modes; performance design: no worker threads, panels redraw only when content changes, not composited when hidden; **no preview/program video**; license not stated on page; 1 star, 0 forks, 9 commits — [GitHub repo](https://github.com/nicolas-riera/OBS-SteamVR-Overlay). A v1.0.0 release page exists ("OBS SteamVR Overlay v1.0.0", October) — [Release v1.0.0](https://github.com/nicolas-riera/OBS-SteamVR-Overlay/releases/tag/v1.0.0). (Conflict: the repo page as fetched showed "no releases"; the release tag page was surfaced by search. Year of the release was not shown; given the 1-star/9-commit state it appears to be very new, plausibly October 2026.)
- **lebaston100/vr-obs-replaybufferbutton** — a single HTML page (`controller.html`) that starts/saves OBS's replay buffer via obs-websocket; "built to sit inside VR, such as on your arm, using XSOverlay or a similar overlay"; setup script fills port/password; requires OBS 29+; MIT; 0 stars, 8 commits — [GitHub](https://github.com/lebaston100/vr-obs-replaybufferbutton).
- **OVR Toolkit** (paid Steam app, appid 1068820) — "Create macro keybinds which can be activated by a click on the wrist to trigger a series of key presses. (Such as changing OBS scenes, muting/un-muting Discord, etc.)"; supports desktop window overlays pinned in VR space — [Steam store](https://store.steampowered.com/app/1068820/OVR_Toolkit__Desktop_Overlay/); [VRChat community wiki](https://wiki.vrchat.com/wiki/Community:OVR_Toolkit). OVR Toolkit forum answers state the overlays do not appear in a game capture in OBS; to capture them you must capture SteamVR's "Display VR View" window or use the OpenVR Input plugin; "The VR view just captures exactly what you see through the VR headset... it's not some OVR Toolkit can control to decide what is visible" — [Steam discussion 1](https://steamcommunity.com/app/1068820/discussions/0/3828662662940006366/); [Steam discussion 2](https://steamcommunity.com/app/1068820/discussions/0/2245552086105452074/); [Steam discussion 3](https://steamcommunity.com/app/1068820/discussions/0/1864993755186129741/).
- **XSOverlay** (paid Steam app, appid 1173510) — "a Desktop Overlay application for OpenVR"; exposes a "Notifications API to allow third-party applications to send toast notifications right to your headset" (UDP, localhost only per a third-party relay project); no WebSocket/control API for OBS was found — [Steam store](https://store.steampowered.com/app/1173510/XSOverlay/); [jonreeve/NotifyXso](https://github.com/jonreeve/NotifyXso). (The GitHub URL `Xiexe/XSOverlay` returned 404; XSOverlay appears closed-source.)
- **Desktop+ (elvissteinjr/DesktopPlus)** — free, GPL-3.0, Windows-only (8.1+, 64-bit) OpenVR overlay in C++ using DXGI Desktop Duplication and optionally Windows Graphics Capture; "smooth, low-latency mirroring of desktops and windows"; overlay width/position/curvature/opacity/cropping with profiles; attach to play space, controllers, trackers or SteamVR Theater Screen; custom laser pointer; VR keyboard with layout editor; user-defined actions bindable to controller inputs/hotkeys/UI buttons; optional CEF-based "Desktop+ Browser" overlays (including transparent pages for web-based stream overlays); Gaze Fade; ~585 stars, 47 forks, 929 commits; release date not shown on fetched page — [GitHub](https://github.com/elvissteinjr/DesktopPlus); [Steam](https://store.steampowered.com/app/1494460/DesktopPlus/). Older sibling: [elvissteinjr/SteamVR-PrimaryDesktopOverlay](https://github.com/elvissteinjr/SteamVR-PrimaryDesktopOverlay).
- **WayVR (formerly WlxOverlay-S, galister/wlx-overlay-s)** — "A lightweight OpenXR/OpenVR overlay for Wayland and X11 desktops" (Rust); screen mirrors, keyboard, taskbar, wrist-mounted watch, edit mode; runs on SteamVR, Monado, WiVRn, Envision, and has "experimental headless support on Steam Frame"; GPL-3.0; ~1.5k stars, 145 forks — [GitHub](https://github.com/galister/wlx-overlay-s).
- **OrbitOverlay (Erik1028/OrbitOverlay)** — "lightweight SteamVR overlay for Windows, in the spirit of XSOverlay and OVR Toolkit": wrist watch, monitors and app windows as curved screens, laser mouse, VR keyboard, layout profiles — [GitHub](https://github.com/Erik1028/OrbitOverlay).
- **OpenVR Advanced Settings** documents SteamVR overlay app keys for per-app bindings: OVR Advanced Settings = steam.overlay.1009850, OVR Toolkit = steam.overlay.1068820, XSOverlay = steam.overlay.1173510, plus Desktop+, fpsVR, LIV — [OpenVR-AdvancedSettings Readme](https://github.com/OpenVR-Advanced-Settings/OpenVR-AdvancedSettings/blob/master/Readme.md).
- **BOLL7708/OpenVROverlayPipe** — displays image overlays/notifications in SteamVR via WebSockets; archived, features moving to BVRTK — [GitHub](https://github.com/BOLL7708/OpenVROverlayPipe).
- VRChat avatar assets ("DXOverlay", "Cyber Window") integrate with XSOverlay/OVR Toolkit/WlxOverlay-S via OSC, which confirms those three as the overlays the VRChat streaming community targets — [DXOverlay on Booth](https://booth.pm/en/items/6262864); [Cyber Window on Booth](https://booth.pm/en/items/5143746).

### Inferences
- The dominant real-world pattern is "flat window in 3D": streamers pin the OBS main window, a browser dock, or a Stream Deck-like web page (e.g. vr-obs-replaybufferbutton) onto a wrist or in space with a generic desktop overlay and poke it with a laser. True spatial UI for OBS does not exist in SteamVR.
- OBS-SteamVR-Overlay is the single most relevant prior-art codebase for *feature scoping* (what an in-headset OBS controller needs: outputs, scenes, studio mode, transitions, full mixer with VU meters, stats) and for *VR ergonomics* (wrist-anchored panel with gaze-angle reveal, dashboard tab, laser or trigger cursor, layout editor, redraw-only-on-change, hide when disconnected). Its stack (raw Winsock + CNG + D3D11 + stb_truetype) is not reusable in a Qt app, and its license is unstated, so treat it as design reference only.
- For the Steam Frame target: Steam Frame runs SteamOS and streams PCVR from a Windows/Linux PC via a dedicated 6 GHz dongle with foveated streaming ([heise](https://heise.de/-11076340); [Road to VR hands-on](https://roadtovr.com/steam-frame-hands-on-valve-vr-headset-index-2)). SteamVR overlays run on the PC and are composited into the stream, so an OpenVR/OpenXR overlay app is the natural "immersive OBS" path there; WayVR's "experimental headless support on Steam Frame" shows a Linux/OpenXR overlay is already being exercised against that device.
- Desktop+ and WayVR demonstrate the capture/compose plumbing (desktop duplication / Wayland capture into an overlay texture, laser-pointer hit testing, VR keyboard) a Qt-based overlay would need if it ever wants to embed the stock OBS window alongside a native spatial UI.

### Gaps
- OBS-SteamVR-Overlay license, exact release date and whether it is maintained could not be confirmed (page did not show dates; 1 star suggests it is brand new and single-author).
- OVR Toolkit / XSOverlay store pages and the VRChat wiki page could not be fetched; feature details rely on search snippets and Steam forum posts (which are "older").
- No usage statistics exist for how many streamers control OBS from inside VR.

## Key Question 3: Are there OBS plugins that expose OBS as an OpenVR/OpenXR overlay or render OBS output into a headset?

### Takeaway
No. Every OBS plugin involving OpenVR/OpenXR goes the other direction (headset image into OBS). Getting OBS output into a headset today means either a desktop-mirroring overlay showing the OBS window, or an external transport (NDI, WHIP/WebRTC, virtual camera, a vendor "feed" plugin) consumed by a separate headset app.

### Cited Findings
- Web search for an OBS preview-in-headset plugin found none; "Every result covers the reverse direction: getting the headset view into OBS" — synthesized across [OBS forum OpenVR-Capture thread](https://obsproject.com/forum/threads/openvr-capture.181854/page-2), [SteamVR streaming discussion](https://steamcommunity.com/app/250820/discussions/0/1499000547491080801/).
- **baffler/OBS-OpenVR-Input-Plugin** — adds an "OpenVR Capture" source that reads the SteamVR mirror texture; Windows 64-bit only, DirectX 11; it also captures any pinned overlay windows because OpenVR "doesn't provide direct access to the game image before overlays are rendered" — [DeepWiki summary](https://deepwiki.com/baffler/OBS-OpenVR-Input-Plugin); [OBS forum thread](https://obsproject.com/forum/threads/openvr-capture.181854/page-2).
- **mcoffin/obs-openvr** — Linux OBS plugin for capturing OpenVR outputs and overlays — [libhunt comparison](https://www.libhunt.com/compare-obs-openvr-vs-OBS-OpenVR-Input-Plugin).
- **elliotttate/OpenXR-Layer-OBSMirror** — native OpenXR API layer + OBS source plugins + WinUI 3 "Control Center"; captures native OpenXR (D3D11/D3D12) apps or SteamVR/OpenVR compositor output into OBS, with recording-only FOV overscan and camera smoothing; Windows x64; MIT; 54 stars; no release listed on fetched page — [GitHub](https://github.com/elliotttate/OpenXR-Layer-OBSMirror).
- Meta's official route for Quest is casting via Meta Quest Link on Windows, which appears "as a webcam source in OBS" — [Meta help](https://www.meta.com/help/quest/1160309589204876/).
- OBS 30.0.0 (released 12 Nov, year not shown on page; 2023 by version history) added a "WHIP/WebRTC output", IPv6 RTMP, SRT fixes, Decklink HDR output, reworked macOS virtual camera, and a "Safe Mode" that disables plugins/scripts/websockets — [obs-studio release 30.0.0](https://github.com/obsproject/obs-studio/releases/tag/30.0.0).
- obs-websocket 5.5.2 (RPC version 1) offers only single-frame `GetSourceScreenshot` / `SaveSourceScreenshot`; "Continuous video stream: None" — [obs-websocket protocol.md](https://raw.githubusercontent.com/obsproject/obs-websocket/master/docs/generated/protocol.md).

### Inferences
- The "capture VR into OBS" plugins are useful only as examples of OBS plugin + D3D11/OpenVR/OpenXR interop code (shared textures, API layers), not as prior art for the product. They should be mentioned in the report purely to disambiguate.
- Because no OBS-side "render to headset" plugin exists, the team's three targets each need their own egress: (1) Vision Pro: the headset app must receive video over the network (WHIP/WebRTC, NDI, or a custom feed) or, for the macOS target, be rendered by the Mac itself via RemoteImmersiveSpace; (2) Steam Frame/PCVR: an OpenVR/OpenXR overlay can read OBS's render texture in-process if the app is an OBS plugin or links libobs.

### Gaps
- No sources measured latency of NDI vs WHIP vs screenshot-polling to a headset; the only latency claims are vendor marketing (Producer Pad, see Q4).

## Key Question 4: What obs-websocket remote clients exist, which run on Vision Pro, and how do they get preview video?

### Takeaway
The obs-websocket client ecosystem is large (OBS Blade, Touch Portal, Bitfocus Companion, StreamControl, CTD Live Mobile, Producer Pad, RealtimeKit, OBS Controller, etc.) and uniformly uses the v5 WebSocket protocol built into OBS 28+. Only OBS Controller lists visionOS. Preview video is the weak spot: obs-websocket has no video stream, so clients either poll `GetSourceScreenshot` (base64 JPEG/PNG, 8-4096 px, quality -1..100) or add a side channel (Producer Pad: NDI or its own "ProducerPad Feed" plugin).

### Cited Findings
- obs-websocket protocol (v5.5.2, RPC 1): `GetSourceScreenshot` takes `sourceName`/`sourceUuid`/`canvasUuid`, required `imageFormat` (formats enumerated by `GetVersion.supportedImageFormats`), optional `imageWidth`/`imageHeight` (>=8, <=4096, "scale to inner"), `imageCompressionQuality` (-1..100); returns base64 `imageData`; studio-mode requests `GetStudioModeEnabled`, `SetStudioModeEnabled`, `SetCurrentPreviewScene`, `TriggerStudioModeTransition`; events `CurrentProgramSceneChanged`, `CurrentPreviewSceneChanged`, `StudioModeStateChanged`; outputs `StartVirtualCam`, `GetOutputList`; no continuous video request — [protocol.md](https://raw.githubusercontent.com/obsproject/obs-websocket/master/docs/generated/protocol.md). The official project notes obs-websocket is "included by default with OBS Studio 28.0.0 and above", default port 4455, password strongly recommended — [obs-websocket on launchpad mirror](https://launchpad.net/obs-websocket); [OBS Remote Control Guide](https://obsproject.com/kb/remote-control-guide).
- **OBS Blade (Kounex/obs_blade)** — Flutter; iOS/Android (App Store, Google Play, F-Droid, GitHub Releases); GPL-3.0; 613 stars, 59 forks, 1,591 commits; connects to OBS WebSocket (OBS 28+ or obs-websocket 5.x; `legacy` branch for 4.x); free features include stream/record/replay/virtual cam control, scene switching with Studio Mode, audio mixer with volume meters, "a live preview of the current scene", stream health stats, chat; Pro tier adds merged chat/emotes/TTS/themes; README does not say how the preview image is obtained — [GitHub](https://github.com/Kounex/obs_blade). (Search for how OBS Blade obtains preview found no documentation; GetSourceScreenshot polling is the only mechanism the protocol offers.)
- **Bitfocus Companion OBS module (bitfocus/companion-module-obs-studio)** — scene/source/audio/recording/streaming control plus custom WebSocket commands for Companion and Bitfocus Buttons; connects over OBS WebSocket (address/port 4455/password, `wss` supported); page states it requires OBS Studio 32.1 or newer; MIT; 56 stars, 36 forks, 470 commits; README does not mention screenshots on buttons — [GitHub](https://github.com/bitfocus/companion-module-obs-studio).
- **Touch Portal** — "#1 All-in-One Remote Control Macro and Stream app for Phones and Tablets"; OBS integration "(OBS web-socket required)", older obs-websocket versions no longer supported; remote (non-localhost) OBS connection "will not work in the free base version" — [App Store](https://apps.apple.com/app/id1410172542); [Touch Portal OBS tutorial](https://www.touch-portal.com/blog/post/tutorials/obs-touch-portal-get-started.php); [OBS forum resource](https://obsproject.com/forum/resources/touch-portal.755/).
- **StreamControl (Android)** — unofficial remote; requires OBS 28+; start/stop stream/record, replay buffer, scenes, volume; "will NOT allow you to stream/record from your phone" — [OBS forum resource](https://obsproject.com/forum/resources/android-streamcontrol-remote-for-obs-studio.821/).
- **CTD Live Mobile (iOS/iPad, paid)** — obs-websocket 5.x remote, same-LAN — [OBS forum "obs remote" tag](https://obsproject.com/forum/tags/obs-remote).
- **Producer Pad (iOS/iPadOS)** — "connects to OBS Studio via WebSocket and shows your Program and Preview feeds on your iPad or iPhone in real-time"; "Low latency video and audio monitoring is supported using NDI or the available free companion plugin (ProducerPad Feed)"; plugin runs on Windows and macOS; scene switching, VU-meter audio mixer, remote text-source editing; QR-code pairing; same-LAN only; requirements OBS 28+ and iOS 17+ (forum) vs iOS 18+ (App Store); 14-day trial then subscription or lifetime — [OBS forum resource](https://obsproject.com/forum/resources/producer-pad.2316/); [OBS forum thread](https://obsproject.com/forum/threads/producer-pad.193391); [App Store](https://apps.apple.com/us/app/-/id6755590424). No public source for the ProducerPad Feed plugin was found.
- **RealtimeKit (iPad)** — free; "allows you to remotely control your OBS... There is no need to set up obs-websocket!" (implies its own OBS-side component) — [App Store](https://apps.apple.com/pl/app/realtimekit/id6443628121).
- **OBSwiftSocket (edonv)** — open-source Swift obs-websocket v5 library, MIT, iOS 13+/macOS 10.15+, SPM; author says it is "currently on pause... mostly works, but has some issues"; usage docs "Examples coming soon!"; companion `wspublisher` built on `URLSessionWebSocketTask` — [Swift Package Index](https://swiftpackageindex.com/edonv/OBSwiftSocket); [Swift Package Registry](https://swiftpackageregistry.com/edonv/OBSwiftSocket).
- Other client libraries listed by the obs-websocket README: obs-websocket-js (JS), obws (Rust, dnaka91), ObsWebSocket.Core (.NET, "strongly typed DTOs generated from the protocol"), obs_websocket (Dart 5.7.0), obs-websocket-py — [README mirror](https://gitee.com/obs_3/obs-websocket); [NuGet](https://www.nuget.org/packages/ObsWebSocket.Core/0.3.2-dev1); [pub.dev obs_cli example](https://pub.dev/packages/obs_cli/example).
- **Switcher (Switcher Inc.)** — multicam live streaming app whose App Store listing includes "Apple Vision / Requires visionOS 1.0 or later" (some regional listings say 2.0); "Use your Mac, iPad, or iPhone as your main camera-changing device"; not an OBS client — [App Store](https://apps.apple.com/us/app/switcher-live-streaming-app/id908386221).

### Inferences
- A Qt immersive OBS client that only speaks obs-websocket inherits the same limitation as every remote: no program/preview video. It needs a side channel. Producer Pad's design (WebSocket for control + NDI or a tiny vendor OBS plugin for video + QR pairing) is the most direct template for the Vision Pro "remote" mode; OBS's built-in WHIP/WebRTC output (since 30.0) is a plugin-free alternative worth evaluating for a WebRTC-capable headset client.
- Screenshot polling via `GetSourceScreenshot` is viable for low-rate thumbnails (scene multiview tiles, 8-4096 px, quality tunable) but not for a 90 Hz program monitor.
- The team's third target (macOS OBS with rendering on Vision Pro) sidesteps all of this: the Mac process already owns libobs's render texture and can push it into a `CompositorLayer` (see Q5).
- Companion's "requires OBS 32.1+" note shows the obs-websocket surface is still evolving (e.g. `canvasUuid` on GetSourceScreenshot for multi-canvas OBS); the client should target the current protocol and read `GetVersion` for capability discovery.

### Gaps
- No evidence of how OBS Blade, Touch Portal, or Companion render preview images (likely GetSourceScreenshot polling, unconfirmed).
- Could not fetch App Store pages, so visionOS compatibility for OBS Blade/Touch Portal/Producer Pad/CTD Live is unconfirmed beyond the listed device families in search snippets (none list Apple Vision).
- No independent latency measurements for Producer Pad's feed plugin or NDI-to-iPad.

## Key Question 5: Have any projects attempted a Qt application in XR, or a Qt Quick 3D Xr app controlling a desktop application? Community discussion of OBS on Vision Pro / VR?

### Takeaway
Qt has shipped the plumbing (Qt Quick 3D Xr, Technical Preview since Qt 6.8, with Apple Vision Pro standalone as a "Tier One" tested device alongside Quest 3; plus a preliminary native visionOS QPA where "QWindows can now be created and shown"), and Apple has shipped `RemoteImmersiveSpace`/CompositorServices in macOS 26 for Mac-rendered immersive content on Vision Pro. No public project was found that uses Qt Quick 3D Xr to control a desktop application, no Qt-in-XR app controlling OBS exists, and no OBS/Qt community discussion of an OBS visionOS/VR port surfaced.

### Cited Findings
- Qt Quick 3D Xr "supports two main platforms: devices that use OpenXR... and devices that use Apple's visionOS"; "currently supports one non-OpenXR platform: Apple's visionOS"; "all features might not be available on all platforms"; Tier One: Meta Quest 3 standalone (Android), Meta Quest 3 PCVR (Windows), Apple Vision Pro standalone (visionOS); Tier Two: Quest 2 standalone, HTC Vive PCVR on Linux; enable the `qt.quick3d.xr` logging category for debugging — [Qt docs: Qt Quick 3D Xr supported platforms](https://doc.qt.io/qt-6/qt3dxr-supported-platforms.html); [6.8 version](https://doc.qt.io/qt-6.8/qt3dxr-supported-platforms.html).
- The module shipped in Qt 6.8 and "is still labeled Technical Preview in later docs"; provides QML types for XR (spatial anchors, passthrough, hand tracking); `XrView` "sets up the view for an XR application... available since Qt 6.8"; 6.9/6.10 docs add types such as `XrHapticFeedback`, `XrSimpleHapticEffect` — [Qt 6.8 QML module](https://doc.qt.io/qt-6.8/qtquick3d-xr-qmlmodule.html); [Qt 6.10 QML module](https://doc.qt.io/qt-6.10/qtquick3d-xr-qmlmodule.html); [heise on Qt 6.8](https://heise.de/-9974750). A Felgo-mirrored page titled "Getting Started With Apple Vision Pro Qt Quick 3D - XR Simple Example" exists — [Felgo mirror](https://felgo.com/doc/qt/qtquick3d-xr-qmlmodule/).
- Qt native visionOS platform work in qtbase: a commit "adds preliminary visionOS support" noting Qt already ran on Vision Pro as "Designed for iPad"; configure with `-platform macx-visionos-clang` (optional `-sdk xrsimulator`); early commits said QWindows could not be created because window management depended on UIWindow/UIScreen; a later commit adopting the UIScene lifecycle states "QWindows can now be created and shown on visionOS", though no `UIApplicationSceneManifest`/multi-scene support is declared yet — [qtbase ios QPA log](https://code.qt.io/cgit/qt/qtbase.git/log/src/plugins/platforms/ios?showmsg=1); [qiosintegration.mm log](https://code.qt.io/cgit/qt/qtbase.git/log/src/plugins/platforms/ios/qiosintegration.mm?showmsg=1).
- OBS 28.0 moved OBS to Qt 6 — [LinuxAdictos on OBS 28 Qt 6 port](https://www.linuxadictos.com/en/obs-studio-28-0-celebrates-its-10th-anniversary-with-the-port-to-qt-6-and-improving-support-for-new-formats.html); [28.0.0-beta1 notes](https://newreleases.io/project/github/obsproject/obs-studio/release/28.0.0-beta1).
- A community "qmlview" OBS plugin adds a source that renders QtQuick/QML files inside OBS; listed as Linux-only, and the author reports filters don't work with it — [OBS forum resource qmlview](https://obsproject.com/forum/resources/qmlview.495); [thread](https://obsproject.com/forum/threads/qmlview.63587).
- Apple `RemoteImmersiveSpace` (SwiftUI): "A scene that presents content in an unbounded space on a remote device"; availability macOS 26.0+; "acts as a container for compositor content presented on the user's chosen visionOS device" — [Apple docs](https://developer.apple.com/documentation/swiftui/remoteimmersivespace.md); [init(id:for:content:)](https://developer.apple.com/documentation/swiftui/remoteimmersivespace/init(id:for:content:).md). `CompositorLayer` is the Metal rendering container used inside immersive spaces, listed with macOS 26.0 availability — [CompositorLayer docs](https://developer.apple.com/documentation/compositorservices/compositorlayer.md).
- 9to5Mac (WWDC25, June 2025): "macOS Tahoe 26 apps will be able to render 3D immersive content directly on Apple Vision Pro, using a brand-new scene type called RemoteImmersiveSpace"; supports "input events, like taps and gestures, and hover effects" — [9to5Mac](https://9to5mac.com/2025/06/12/macos-apps-can-now-render-3d-scenes-directly-on-apple-vision-pro/).
- Apple Developer Forums (Vision Pro engineer reply): Mac spatial rendering connects wirelessly or over USB with the developer strap, one device at a time; "Mixed mode isn't supported, only full and progressive immersion"; RealityKit is not available, so rendering must be Metal 3 or Metal 4; the relevant WWDC25 session is referenced as "What's new in Metal rendering for immersive apps" — [Apple forum thread 787528](https://developer.apple.com/forums/thread/787528).
- **Spatial Render (Mac app)** uses this: "streams a Mac's screen to Vision Pro over Wi-Fi", "supports streaming from HDMI capture cards connected to your Mac", "uses the Remote Immersive Rendering feature in macOS Tahoe and visionOS 26"; requires macOS 26+ on Apple Silicon; up to "2.5K@90Hz per eye" — [App Store (MX)](https://apps.apple.com/mx/app/spatial-render/id6751405237); [App Store (QA)](https://apps.apple.com/qa/app/spatial-render/id6751405237?l=ar).
- Searches for "OBS Studio Qt Quick QML visionOS port", OBS forum "Vision Pro", and obs-studio GitHub issues returned no community discussion of an OBS visionOS or VR port (see Q1 citations).

### Inferences
- The team's stack choice is validated by Qt's own tiering: Vision Pro standalone and Quest 3 PCVR (a stand-in for SteamVR/OpenXR on Windows) are both Tier One for Qt Quick 3D Xr; Linux PCVR (the likely Steam Frame streaming host OS besides Windows) is only Tier Two. Expect Technical-Preview-grade rough edges and platform-specific feature gaps.
- There is a meaningful distinction between (a) running the *existing* Qt Widgets OBS UI on visionOS via the preliminary native QPA (now able to show QWindows, but with no multi-scene manifest, so one flat window) and (b) a Qt Quick 3D Xr app with XrView/XrItem spatial UI. No one has done (a) for OBS; (b) is the "true spatial UI" route.
- For the "macOS with rendering on Vision Pro" target, `RemoteImmersiveSpace` + `CompositorLayer` is the only Apple-sanctioned mechanism; its constraints (Metal-only, no RealityKit, full/progressive immersion only, no mixed/passthrough, single device, wireless or dev-strap USB) directly shape what an OBS-on-Mac immersive view can be. Spatial Render proves a shipping third-party Mac app can stream a screen/capture-card feed this way at up to 2.5K@90Hz per eye.
- A Qt Quick 3D Xr app has no documented bridge to `RemoteImmersiveSpace`; the macOS target will likely need a native Swift/Metal host that consumes libobs's texture, separate from the Qt XR client.

### Gaps
- doc.qt.io and the Felgo mirror could not be fetched, so the exact XrItem/XrView/XrInputAction API surface and visionOS input (gaze+pinch) behavior in Qt Quick 3D Xr were not read first-hand; only the supported-platforms page content (via search) is cited.
- Could not confirm which Qt release (6.9/6.10/6.11) the visionOS QPA "QWindows can now be created" commit shipped in, nor whether Qt officially lists visionOS as a supported platform for Qt Widgets.
- No example or blog post of a Qt Quick 3D Xr app driving an external desktop app was found; no OBS-forum or GitHub discussion of OBS in VR/visionOS was found.

## Key Question 6: What Meta Quest / Horizon apps exist for streaming production?

### Takeaway
Quest has no OBS client or production-control app; the relevant apps are desktop-mirroring tools (Virtual Desktop, Immersed, Horizon Workrooms, Microsoft's Windows remote desktop) that can show the flat OBS window, plus a few headset-to-Twitch streamers (BeamXR, Lumen Live Studio, Vstamer) and Meta's cast-to-OBS webcam route. Horizon OS itself composes apps as floating 2D windows in 3D (up to six anchored), which is the same "flat panels in space" paradigm as visionOS windows.

### Cited Findings
- Virtual Desktop "now streams multiple monitors"; Quest 3 "is the only headset that can support 3 monitors at once" (one at 4K or multiple at 1440p); Immersed and Horizon Workrooms also stream multiple monitors — [UploadVR](https://www.uploadvr.com/virtual-desktop-multiple-monitors-update/). A user review reports Horizon OS updates "increasingly interfering with the functionality of Virtual Desktop Streamer" (single anecdote) — [Meta app referral page](https://www.meta.com/appreferrals/Stylistme/2017050365004772/).
- Microsoft's Windows 11 remote desktop app for Quest (with Horizon OS v81) "can beam multiple high-resolution monitors" via Mixed Reality Link, in immersive or passthrough mode — [article](https://rss.boorghani.com/?p=362208).
- Horizon OS: apps are "floating 2D windows which can be arranged in 3D space"; newer versions allow anchoring "three in each modality, for a total of six" — [UploadVR on v81](https://uploadvr.com/quest-v81-new-immersive-home-window-anchoring-quickplay); [Meta Horizon OS (Wikipedia)](https://en.wikipedia.org/wiki/Meta_Horizon_OS).
- An OBS forum thread reports Immersed working with OBS on Quest 2 but recording failing with three or more virtual screens open — [OBS forum: immersed obs bug](https://obsproject.com/forum/threads/immersed-obs-bug.165674/).
- Bigscreen (2020) added a green-screen room and "Selfie Stick" streamer camera that fed a desktop capture to OBS — [VRScout](https://vrscout.com/news/bigscreen-vr-green-screen-room-update).
- Quest cannot natively stream to Twitch/YouTube; workarounds are casting to a desktop browser captured by OBS, or third-party apps — [Meta community forum thread](https://communityforums.atmeta.com/discussions/OffTopic/feature-request-live-streaming-to-youtube-and-more-natively-from-the-meta-quest-/1338434). BeamXR Live (Horizon Store early access) streams directly from Quest to Twitch/YouTube with no PC — [Road to VR](https://roadtovr.com/?p=173045). "Lumen Live Studio" (vendor sales page, unverified) claims Quest-to-Twitch/YouTube and OBS browser-source output — [Payhip](https://payhip.com/b/csFdu).
- Meta's official cast-to-OBS route: Meta Quest Link on Windows exposes the cast as a webcam source in OBS — [Meta help](https://www.meta.com/help/quest/1160309589204876/).
- Qt Quick 3D Xr lists Meta Quest 3 standalone and Quest 3 PCVR as Tier One devices (see Q5) — [Qt docs](https://doc.qt.io/qt-6/qt3dxr-supported-platforms.html).

### Inferences
- A Quest build of the Qt immersive OBS client is technically the best-supported Qt Quick 3D Xr target (Tier One, OpenXR, Android) and would fill a genuine gap, but it is outside the team's stated first three targets; the report should note it as a cheap follow-on if the OpenXR path is built for Steam Frame.
- Immersed/Virtual Desktop usage with OBS on Quest is "flat OBS window in a virtual monitor", with known fragility (the Immersed multi-screen bug), reinforcing that desktop mirroring is not a satisfying production tool.

### Gaps
- No 2025-2026 changelogs for Immersed or Virtual Desktop were retrieved; no information on whether any Horizon Store app speaks obs-websocket.

## Key Question 7: Academic or commercial "spatial video production" tools resembling a live production control room in XR?

### Takeaway
Live *delivery* of immersive video to Vision Pro is maturing (Blackmagic URSA Cine Immersive 100G + URSA Live Encoder, SpatialGen Zeus, Apple's Lakers streams, Sandwich's viewer-switched "Talk Show Live"), and Mac-to-headset rendering tools exist (Spatial Render), but no product puts the *control room* (switching, mixing, monitoring) inside the headset. Switcher's visionOS listing is the only multicam-production app with a Vision Pro entry, and its role there is unclear.

### Cited Findings
- Blackmagic URSA Cine Immersive: $29,995, dual 8K stereoscopic 180-degree capture up to 90 fps for Apple Immersive Video; the live-oriented "URSA Cine Immersive 100G" pairs with the "URSA Live Encoder" which compresses to ProRes and outputs SMPTE-2110-22 IP video; used to stream Los Angeles Lakers games to Vision Pro; DaVinci Resolve gained immersive editing — [heise](https://heise.de/-11257515); [ASC](https://theasc.com/articles/blackmagic-design-announces-camera-workflow-for-apple-immersive-video); [iThinkDiff](https://www.ithinkdiff.com/blackmagic-ursa-cine-immersive-vision-pro/).
- SpatialGen Zeus: 3U rack-mounted system "built for live immersive video workflows, including Apple Immersive Video" — [UploadVR](https://www.uploadvr.com/spatialgen-zeus-streams-live-immersive-video-to-apple-vision-pro/).
- Sandwich's "The Talk Show Live 2025": viewers "direct their own experience by switching between cameras in real-time inside Apple's Theater app" (viewer-side switching, not production) — [Sandwich press](https://sandwich.vision/press/TTS-Live-2025/).
- Voodoo Spatial (iPhone) livestreams spatial video to a Voodoo Spatial Player on visionOS — [App Store](https://apps.apple.com/is/app/voodoo-spatial/id6497950663).
- Spatial Render (Mac): Mac screen / HDMI capture-card streaming to Vision Pro using macOS 26 Remote Immersive Rendering, up to 2.5K@90Hz per eye — [App Store](https://apps.apple.com/mx/app/spatial-render/id6751405237).
- Switcher (multicam live streaming): App Store listing includes Apple Vision (visionOS 1.0/2.0+ depending on region) — [App Store](https://apps.apple.com/us/app/switcher-live-streaming-app/id908386221). No vMix or ATEM-control app for Vision Pro was found; LiveApp Pro (ATEM-integrated playback) lists iPad/Mac only — [App Store](https://apps.apple.com/app/id1555714698).

### Inferences
- The industry is building the *pipeline* (immersive cameras, encoders, delivery) and leaving the *control surface* on Macs/iPads. An immersive OBS control room is a whitespace, and Spatial Render demonstrates the exact macOS-26 mechanism the team's third target depends on, applied to video monitoring.
- The viewer-side multi-camera switching in Apple's Theater app (Talk Show Live) hints at how a program/preview multiview could feel on visionOS, but no SDK or source is available.

### Gaps
- No academic papers on XR live-production control rooms surfaced in the searches run (searches focused on products; an ACM/IEEE-specific search was not performed).
- Switcher's exact behavior on Vision Pro (switcher vs camera role) is unconfirmed.
