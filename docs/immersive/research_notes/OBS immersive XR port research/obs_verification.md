# Verification addendum: OBS-related claims re-checked against primary sources

Verification date: 2026-10-22. Scope: every finding in `obs_control_layer.md` and `existing_projects.md` that was sourced from a search snippet, a mirror, or marked as a gap because obsproject.com, docs.obsproject.com, ndi.video, GitHub release pages or the App Store were unreachable. This file does not replace the original notes; it records verdicts (CONFIRMED / CORRECTED / COULD NOT VERIFY), corrected text, and primary-source quotes.

Reachability notes for the report writer (so the method is reproducible): `docs.obsproject.com`, `obsproject.com` (download, blog, KB, forum, resource manager), `ndi.video`, `docs.ndi.video` (GitBook; append `.md` to any page URL for Markdown), `apps.apple.com`, `itunes.apple.com` (lookup API), `raw.githubusercontent.com`, `newreleases.io` and `git clone`/`git ls-remote` against github.com all worked through the sandbox proxy with `curl`/`git`. The `WebFetch` tool could not resolve `obsproject.com` hosts, and `github.com` HTML plus `api.github.com` were blocked for `curl`/`gh` (session is repository-scoped), but `WebFetch` could read github.com issue/PR/release pages. Where a GitHub release page could not be read, dates were taken from the signed tag objects (`git cat-file -p <tag>`), which match the release page dates within a day.

## Key Question 1: docs.obsproject.com — frontends init sequence, obs_display and the macOS caveat, frontend-API reference, main-texture/raw-video callbacks, Canvas API stability

### Takeaway
Everything the notes quoted from the local `docs/sphinx/*.rst` is identical on the live site and on upstream master. Two precision corrections: (a) several libobs functions the notes rely on (`obs_get_main_texture`, `obs_render_main_texture_src_color_only`, `obs_add_raw_video_callback2`) and the three frontend canvas functions are **not documented at all** on docs.obsproject.com (they exist only in headers), and (b) the documented frontend API is ~93 functions (94 `.. function::` directives), not "100+".

After that, modules typically should be loaded." Verdict: **CONFIRMED** verbatim on the live page and upstream rst: "To initialize libobs, you must call obs_startup(), obs_reset_video(), and then obs_reset_audio(). ### Gaps
- No docs statement anywhere on thread affinity of `obs_add_main_render_callback` or on calling `obs_get_main_texture()` outside a render callback (unchanged gap).
